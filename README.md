# Тихий зал

Сайт камерных концертов по пятницам: афиша, подробности о формате вечера и запись на концерт. Учебный проект: «Тихий зал» выдуман, даты, цены и контакты примерные.

Превью: https://verver-vadya.github.io/site-tikhiy-zal/ (после слияния в `main` и включения Pages).

Стиль навеян портфолио Марии Васильевой (страница проекта Sierra): чёрные боковые полосы, тонкие линейки как нотный стан, узкие заголовки с подписями-сносками, машинописный текст и пометки от руки. Тексты, фото и код свои.

## Что внутри

- одна страница `index.html`: первый экран с «нотами»-фото и указателем ближайшего концерта, афиша, подробности, «Как проходит вечер» с указателем, который едет по нотному стану при прокрутке, форма записи;
- `assets/css/style.css`: токены (бумага, тушь, красный карандаш) в начале файла;
- `assets/js/main.js`: меню (Esc, клик вне), выключатель пометок от руки (запоминается), ближайший концерт по текущей дате, выбор концерта в форме из афиши, указатель воспроизведения;
- `assets/js/form.js`: проверка и отправка формы из шаблона;
- шрифты Oranienbaum, IBM Plex Mono и Bad Script лежат в `assets/fonts/` (OFL);
- фото из общественного достояния (CC0 / Public Domain Mark), список источников в `assets/img/CREDITS.md`.

## Что заменить перед запуском

- даты, программы и цены в афише (`index.html`, блок `.gigs`, и список в форме);
- почту `hello@tikhiy-zal.ru` в подвале;
- адрес Formspree вместо `YOUR_FORM_ID`;
- данные владельца в `privacy.html` (всё в `[ЗАПОЛНИТЬ: …]`);
- `canonical`, Open Graph, `sitemap.xml` и `robots.txt`, если у сайта будет свой домен.

## Запуск локально

Сборки нет, нужен любой статический сервер:

```bash
python3 -m http.server 8000
# или
npx serve .
```

Открыть http://localhost:8000.

## Автопроверка

Ловит типичные ошибки: ссылки на `#` и битые ссылки, кнопки без реакции на наведение и нажатие, форму, которая молчит при ошибке или отправляется дважды, меню, которое не закрывается, ошибки в консоли, горизонтальную прокрутку на 375 / 768 / 1280, мелкие зоны нажатия, сломанную 404, заглушки и штампы в текстах. Делает скриншоты трёх ширин.

- **В pull request** запускается сама (Actions → «Проверка сайта»). Отчёт в Summary, скриншоты в артефакте `screenshots`.
- **Локально** (нужен Node.js 20+):

  ```bash
  cd .github/check
  npm ci
  npx playwright install chromium   # один раз
  npm run check                     # черновик: заглушки только предупреждают
  npm run check:release             # перед публикацией: заглушки тоже ошибки
  ```

  Отчёт и скриншоты появятся в папке `.check/`.

Чего проверка не видит (дизайн, смысл текстов, «шаблонность»), смотрим руками по `.github/CHECKLIST.md`.

## Публикация

- **Превью**: автоматически на GitHub Pages после пуша в `main` (`https://<логин>.github.io/<репозиторий>/`).
- **Боевой сайт**: загрузить файлы на российский хостинг (Timeweb, Beget, Reg.ru) по FTP/SFTP или в Yandex Object Storage, без папок `.github`, `.claude`, `.check` и `node_modules`. Настроить на хостинге `404.html` как страницу ошибки 404. Перед этим пройти `npm run check:release`. Только после явного согласия владельца.

## Изображения

Фото и иллюстрации хранить в `assets/img/` в WebP или AVIF, с `width`/`height`, `alt` и `loading="lazy"` (кроме первого экрана). Не ссылаться на картинки со сторонних сайтов.
